# Omni V2 — S1/S2 Gap Audit

## Status correction

S1 and S2 are **implemented but not certified**. The previous completion claims were too broad because the code delivered a functional skeleton rather than the full buyer interface contract.

## Confirmed gaps

| Area | Current state | Required recovery |
|---|---|---|
| Map scene | MapLibre canvas exists, but the scene lacks the complete globe-first presentation and user-facing map controls | Add globe state treatment, explicit recenter/rotation controls, location marker state and stable scene chrome |
| Top chrome | Only Omni label and a recenter button exist | Add compact identity, location status, map control group and safe mobile layout |
| Search dock | Basic label, input, submit and text Options button | Add clear affordance, submit/loading/error states, options popover, result count and visible-bounds context |
| Options | Button only writes a status sentence | Add a real non-destructive options sheet with scope, nearby/follow-location and map presentation controls |
| Location | Browser request exists, but no visible user marker or persistent exact/approximate state | Render exact/approximate location state and recoverable permission/timeout messaging |
| Map controls | Navigation control is mounted but not composed into the Omni UI contract | Add visible recenter, rotation pause/resume and zoom controls with responsive placement |
| Discovery results | Cards exist but result presentation is visually minimal and not fully state-driven | Add result header, loading/empty/error/retry surfaces, result selection and return path |
| Facility detail | Public detail and catalogue exist but are compressed into one generic sheet | Add deliberate identity, media, metadata, catalogue entry point and clear back-stack behavior |
| Catalogue | Product cards exist but catalogue search and selection feedback are weak | Add catalogue toolbar, product count, empty state, selection summary and next-step lock explanation |
| Responsive behavior | No dedicated 320/375/768/1280 evidence | Add responsive states and run click-through at all four widths |

## Recovery scope

The recovery slice must remain S1/S2 only. It may add buyer UI composition, map controls, public location visualization, discovery state surfaces and catalogue presentation. It must not add availability, seller onboarding, claim certification, intent, QR, chat, payments or wallet behavior.

## Certification gate

S1/S2 cannot be marked complete until a stranger can perform `idle globe → location choice → search → visible results → facility detail → catalogue → product selection → return`, and each loading, empty, error, permission and back-navigation branch is observable in the UI.
