# Omni V1 Field Gap Matrix

**Status:** `ready for contract freeze`  
**Baseline:** `main` at the inherited clean baseline `823981b`  
**Authority:** `OMNI_MASTER_PRODUCT_INTERFACE.md` plus the current V1 continuity matrix  
**Purpose:** classify the remaining gap independently as visual, flow/logic, backend/data, and proof debt before implementation.

## Executive assessment

Omni is not missing one isolated feature. It contains substantial working infrastructure, but the user-visible product is still **partially connected**: the buyer map and discovery foundations exist, the purchase-intent backend already applies server-side pricing and coupons, and the seller route is map-backed, yet the authoritative state model, seller operational composition, external-payment semantics, wallet proof, and cross-role certification are not unified enough to call the field loop ready.

The principal risk is not the absence of code. It is **contradictory state ownership**: parts of the current UI and backend still encode older decisions about QR timing, payment confirmation, seller navigation, and wallet capabilities. The first implementation slice must therefore stabilize the search/auth/discovery contract before expanding seller or wallet surfaces.

## Gate 0 conclusion

The baseline is `ready for contract freeze`, not ready for a broad code rewrite. Slice A is the correct first implementation slice because it removes the largest product ambiguity: whether Omni is a map-first search engine that can preserve context through authentication and show truthful source-backed results. Slice B follows because transaction intent cannot be trusted until availability and privacy semantics are stable.

No production-readiness claim is made by this audit. The remaining work is now bounded by the approved recovery plan and must be reported per slice as `verified`, `partial`, `blocked`, or `needs-decision`.
