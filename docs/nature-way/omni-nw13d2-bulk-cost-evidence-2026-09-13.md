## History and rationalité

- **Amendement D-G** (fondateur, 2026-09-13 « oui approuve go »): le modèle `1 crédit/facilité` de NW-13d est remplacé par le **bulk prix par tranche de 100** — coût prévisible pour les grosses listes, **vérif mono-facilité gratuite** (levier d'adoption), **refus chiffré** (montant manquant visible). L'UI donne le contrôle du coût via la sélection et le rayon.
- **NW-13d-2 étapes:** serveur (manuel 0 + `createBulkAvailabilityRequest` avec `facilityIds[]`, paramétrisation `(${ids})::text[]::uuid[]` sans concaténation SQL), HTTP (`validateBulkAvailabilityRequestCreate` + route), client (`requestBulkAvailability` + `BulkAvailabilityResult`), UI (encart coût en direct + rayon + cases + UN bulk), tests, preuve DB canonique (T1-T5), docs.
- **Honnêteté:** le calcul du coût reste partagé (JS `Math.ceil` du pre-check = valeur injectée dans `credit_spend`); le guard SQL ré-évalue; la route HTTP bulk n'est pas exercée end-to-end en prod (pas de push) — documenté.
- Suite monte **367 → 375 tests** (+8): repo 5 (manuel gratuit adapté, bulk scope, refus épuisé, borne 150→2, rejet <2), http 4 (409 disruptif, 403 chiffré, normalize, reject), api 1 (serialization bulk), 4 tests http adaptés.
