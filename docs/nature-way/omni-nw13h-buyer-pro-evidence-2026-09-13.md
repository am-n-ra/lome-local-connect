## History and rationalité

- **État avant NW-13h (scoping):** l'offre acheteur était absente. Favoris non persistants (jamais stockés), comparateur non limité (Free/Pro indifférencié — incarné plus tard en `compareBlocked`), aucun entitlement acheteur, kind wallet dédié absent (CHECK sur ledger ne comprenait pas `buyer_pro_spend`), plan de crédit bulk toujours `free` (quota 3), et le renouvellement acheteur n'existait pas. Le seller Pro (NW-13g) avait déjà la mécanique entitlement/opt-out/rappel — le buyer Pro la reflète.
- **Décisions fondateur (NW-13b réamendé 2026-09-11, arbitrage 2026-09-13):** D-K **Acheteur Pro maintenant**; prix verrouillé **2 500 XOF/mois = 250000 minor**; défauts recommandés **(a)** pour les 4 points d'arbitrage: (1) favoris persistants — table dédiée `v2_account_favorites` (star sur carte/détail), sauvegarde de recherches déjà distincte (`v2_saved_searches`); (2) activation = paiement wallet véridique — nouveau kind `buyer_pro_spend`, entitlement compte 30 j; (3) opt-out/rappel symétriques au seller (NW-13g), objet `v2_buyer_pro_*` au lieu de détourner `v2_facility_entitlements` (scoping facility); (4) plan de crédit bulk `pro` — `v2_buyer_credit_accounts.monthly_quota` passe à 100 à l'activation.
- **Étapes NW-13h:** migrations 048 (favoris) + 049 (entitlement compte + kind + renewal runs), repo (`listFavorites`/`addFavorite`/`removeFavorite` + `getBuyerProStatus`/`activateBuyerPro`/`setBuyerProRenewalOptIn`/`renewBuyerPro` avec **fix stale accountId** dans le CTE), HTTP (7 routes buyer), client/types (9 fonctions + 6 types), UI (étoile favori + sheet favoris + carte Buyer Pro wallet/plans + quota comparateur + gate openCompare), tests (repo 14, http 1, api 4), preuve DB canonical live, docs.
- **Honnêteté:** le renouvellement acheteur est **payant** et **jamais silencieux** (spend `buyer_pro_spend` référence `buyer-pro:{period}`, opt-in par défaut `false`); quand le solde manque → `insufficient_funds` audité, plan reste `pro_expired`, UI affiche le rappel. Le seed proof du ledger a été purgé proprement (disable→delete→enable trigger append-only, tgenabled=`O`, 0 trace) — le ledger canonique reste intègre. Les migrations 048+049 ont été **appliquées canonical** 2026-09-13 (registre `1055b32c…` + `1819973a…`, re-run `already_applied`).
