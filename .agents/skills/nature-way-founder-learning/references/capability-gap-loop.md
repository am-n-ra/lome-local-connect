# Capability Gap Loop Reference

Use this record to decide whether a founder or team should learn, hire, delegate, use a tool, seek expert input, or defer a capability need.

| Field | Record |
|---|---|
| Active milestone and primary gate | The venture outcome currently blocked or at risk. |
| Observable gap | Specific work that cannot be completed or judged reliably. |
| Evidence / consequence | What happened, what risk exists, and what is affected. |
| Capability area | The relevant practical domain. |
| Response decision | Learn, hire/contract, advisor, tool/system, delegate, defer/decline. |
| Why this response | Capacity, urgency, required depth, credential boundary, and strategic importance. |
| Practice or work artifact | A real interview, analysis, prototype, experiment, brief, or decision. |
| Feedback source | Customer, mentor, expert, peer, system, or outcome signal. |
| Transfer signal | What change in venture evidence would demonstrate useful capability. |
| Boundary | What still requires qualified professional or another owner. |
| Review | Date/event and owner. |

## Practice design

1. Select one live artifact that the current milestone genuinely needs.
2. Learn only enough theory to attempt the artifact honestly.
3. Practise, obtain feedback, revise, and compare the result with the original evidence gap.
4. If transfer is weak, change the practice, feedback source, or response decision; do not simply add more content.
5. Close the record only when the artifact changes the active venture work or the gap has been responsibly transferred to another owner.
